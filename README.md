# Lets Karaoke

本项目是一个本地运行的歌词对齐与卡拉 OK 字幕生成工具。输入音频、视频和歌词后，程序可以完成音频处理、歌词对齐、置信度诊断、人工锚点修正与字幕渲染。

仓库只包含通用源代码、合成测试数据和文档，不包含真实歌曲、受版权保护歌词、模型权重、视频或任何个人机器上的运行记录。

## 环境

- Windows 11
- 系统 Python（直接安装依赖，不使用项目虚拟环境）
- NVIDIA CUDA 环境可用于加速
- FFmpeg、PyTorch 及其他依赖见 `requirements.txt`
- 模型下载到本地缓存目录，不进入 Git 仓库

运行环境检查：

```bat
python src\check_environment.py
```

安装依赖：

```bat
setup.bat
```

## 使用

启动网页界面：

```bat
webui.bat
```

在网页中上传自己的音频、视频和歌词，生成字幕并查看逐句对齐依据。调整锚点后，可以重新对齐、渲染或保存历史版本。

## 技术路线

项目采用“歌词文本驱动、声学时间对齐、规则校正、可解释复核”的处理链：

1. **输入检查**：读取音频或视频，检查编码、采样率、时长和歌词格式。
2. **音频准备**：从视频抽取音频；需要时分离人声，减少伴奏对对齐的干扰。
3. **歌词获取**：优先使用用户提供的 TXT、LRC、SRT 或直接粘贴的歌词。没有歌词时，可以先用 ASR 生成草稿，再人工校对。
4. **时间对齐**：默认使用 Whisper/stable-ts 对已知歌词做逐词、逐字对齐；SOFA 后端适合需要音素级细化的歌声场景。
5. **对齐校正**：执行断档重排、低置信度定位、起点吸附、拖音延长、尾部收回、单调性和重叠检查等通用规则。
6. **结果诊断**：为每句歌词记录时间范围、置信度、声学依据和需要复核的原因，帮助快速定位可疑句子。
7. **字幕渲染**：生成增强 LRC、SRT 或 ASS，并用 FFmpeg 烧录到视频；每次调整都可以保存为独立版本。

## 网页使用方法

1. 运行 `webui.bat`，在浏览器打开显示的地址。
2. 上传视频或音频；如果同时上传视频，输出会保留原视频画面。
3. 粘贴歌词或选择歌词文件，并选择歌词语言。已有歌词时使用“我有歌词”模式。
4. 选择对齐后端和输出样式，点击开始生成，等待任务完成。
5. 在结果区播放视频。点击“定位当前播放歌词”可以跳到正在播放的句子。
6. 展开逐句列表查看起点、终点、置信度和对齐依据。低置信度、无声学证据或时间冲突的句子会标记为需要复核。
7. 直接修改某句的起点和终点并试听；确认后可以把该句设为锚点，让后续歌词从锚点重新计算。
8. 需要补充歌词时，在“插入新的歌词”区域选择插入位置，再选择自动重新对齐、重新渲染或手动填写起止时间。
9. 保存新版本后，可在历史记录中恢复、重新渲染、删除单条或批量清理记录。

## 推荐方法

### 已有准确歌词

推荐使用 **Whisper 对齐 + 默认规则 + 人工复核可疑句**。先让系统完成全曲，再只处理标记出的句子；不要一开始就修改全部高级参数。

### 日文或音素细节要求较高

先使用 Whisper 得到稳定的行级时间，再尝试 SOFA 做音素级细化。若歌词含大量英文、特殊符号或非标准读法，优先保留 Whisper 结果并人工检查。

### 没有歌词文件

使用“自动转写”生成草稿，先校正文案和分行，再重新进行已知歌词对齐。ASR 草稿适合建立初稿，不建议直接当作最终歌词。

### 现场录音或伴奏很重

保留默认的人声引导和双路取优策略。若出现整句漂移，先调整该句锚点；若大量句子同时漂移，再检查人声分离、语言选择和歌词分行，而不是逐句盲调。

### 高级参数的使用原则

高级参数用于处理明确的失效模式：`gap_max` 控制句内断档判定，`start_snap` 控制起点吸附，`tail_extend` 和 `tail_clamp` 控制拖音与尾部收回，置信度阈值控制自动修正范围。修改后应重新生成并查看诊断结果；不确定时恢复默认值。

## 输出与人工复核

系统会同时保留机器结果和人工调整后的版本。建议先检查低置信度句、没有声学证据的句、与相邻句重叠的句，以及播放器当前位置附近的句子。锚点调整只影响锚点之后的时间计算，不会覆盖此前已确认的句子。

- `docs/DEPENDENCY_LICENSES.md`：依赖许可证说明
- `.gitignore`：模型、媒体、缓存和本地结果的排除规则
