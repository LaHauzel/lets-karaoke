# 多轨 MKV 与存储整理

双语修复导出默认将四种软字幕组合封装到一个 MKV：一路视频、两路音频、两路 ASS 字幕。原文／双语与原唱／伴奏可自由组合。默认播放原唱和原文字幕；支持 ASS 的本机播放器中可切换轨道。投稿用硬字幕 MP4 继续独立生成。

网页中的四种选择使用不同复核身份，但路径指向同一文件。统计按文件路径去重，定位与复制路径均指向共享 MKV。网页显示需要选择的音轨和字幕轨，不会自动操控外部播放器。继续编辑使用同时间轴的原文原唱素材。

## 后续导出

`repair_delivery.py` 在提供翻译缓存、导出软字幕时默认使用多轨布局；仅原文导出仍保存两种音轨版本。可以显式选择旧布局：

```powershell
python src/repair_delivery.py <候选目录> <新成品目录> --translation-cache <本地译文缓存> --soft-layout separate
```

缓存按输入文件身份与输出签名检查，重复导出可复用已有多轨文件。该功能不会重新进行 Whisper、翻译或人声分离。

## 迁移已有四版本成品

先生成本地计划，再执行封装。下列路径为示例，应替换为自己的成品库和审计目录：

```powershell
python src/archive_library.py out/concert-collection/exports --audit-dir .local-audits/multitrack
python src/archive_library.py out/concert-collection/exports --audit-dir .local-audits/multitrack --apply
```

计划阶段和封装阶段的跳过项都会写入 `--audit-dir` 下的 `migration-failures.json`，命令仍以非零退出码结束；`--limit` 只限制实际封装的歌曲数量。若成品库自身有诊断错误（清单缺失、路径越界等），仍会整体中止，需先修复。

工具逐曲校验四个版本的视频、音频、字幕包内容。只有共享画面及两组音轨／字幕一致，才合并。它依据视频时间轴统一原有封装延迟，保留音画与字幕的相对时序。每个源文件及输出文件均检查完整数据包内容和时间戳，允许至多 1 毫秒的容器取整差异；另做双音轨和画面的解码抽检。首个音频编码延迟包在零点之前时，容器可能不提供其负时间戳或时长；这一包仍校验内容，之后的可播放包严格比较时间戳。不是完整且唯一的四个软字幕版本、或封装校验不通过的歌曲会被跳过并列入 `migration-failures.json`：原文件保留，其余歌曲继续。

成功后写入 `multitrack-manifest.json`。这是原成品清单之上的存储映射，不改歌词、质量报告或人工审批。四个旧版本映射为四种独立选轨身份。当前／历史／备份批注及工作区引用的原片继续保留，不把旧“通过”状态转给新文件。

迁移命令**不会删除旧媒体**，只生成 `cleanup-candidates.json`。实际清理应在网页和编辑入口测试通过后进行：重新读取审批与工作区依赖、核对原片和归档签名、验证路径仍位于成品库内，再删除没有引用的替代文件。清理失败可重试；不要删除归档映射后再删除原片。应保留审计数据与原清单。

`--limit 1` 可先验证一首歌。重复执行自动跳过已注册的多轨成品。若较新导出覆盖了原路径，签名不匹配时存储映射不会遮盖该新文件。

## 复核清单如何读取

- `multitrack-manifest.json` 使用 `schema_version: 1`。复核页只接受该版本；清单损坏或版本未知时显示诊断并跳过存储覆盖，原清单仍可使用。
- 被新修订替换的成品记录写入 `revisions/history.json`（`schema_version: 1`，`revisions` 数组），历史修订保留各自的歌词与证据；旧裸列表格式仍可读取，下次注册时升级为带版本格式。
- `library-metadata.json` 的 `revision_report` 可指定自定义修订报告路径；留空或为 `null` 时使用 `revisions/index.html`。

## 边界

- 不处理已烧录不同字幕的 MP4 画面去重。
- 不删除源素材、对齐数据、字幕、模型或审批记录。
- 文件大小和文件数按路径去重；跨目录硬链接的磁盘数据量仍需单独分析。
- 同一归档的不同组合拥有不同 ID，复核必须选择实际检查的组合。
- 本地歌词、模型、成品、清单与审计记录均属于私有运行数据，不能提交到 Git。
