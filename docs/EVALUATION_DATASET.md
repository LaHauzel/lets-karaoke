# 对齐评测集：格式、内容与用途

评测集是一组**具体录音版本 + 独立人工标注 + 固定评测方法**。它用来判断改动是否真的减少错位和漏句。模型置信度、能量覆盖、结构健康和历史调参检查点都不能替代人工真值。

## 文件格式

一段录音对应一个 UTF-8 JSON 标注文件。完整格式示例见 [人工标注示例](examples/alignment-reference.json)，输出示例见 [预测时间轴](examples/alignment-prediction.json)。两者使用原创虚构句子和时间，不对应真实歌曲，也不代表已建立了真实真值集。

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `schema_version` | 当前为 1 | 避免不同格式混用 |
| `recording_id` | 某一次录音的唯一编号 | 现场版、录音室版、剪辑版分别编号 |
| `audio.file` | 相对文件名 | 在本地定位媒体，不记录个人绝对路径 |
| `audio.sha256` | 实际文件的 SHA-256 | 防止换版本或剪掉前奏后继续使用旧标注 |
| `audio.duration_s` | 总时长，秒 | 验证时间边界 |
| `language` | 主语言 | 按语言分组比较 |
| `split` | `train`、`dev` 或 `test` | 调参只用 dev；最终报告使用未参与调参的 test |
| `annotation` | 标注方式、修订号、是否复核 | 明确真值来源与版本 |
| `lines[].id` | 每次出现的歌词都有唯一编号 | 重复副歌也分开编号，避免配错位置 |
| `text` | 实际演唱文本 | 保留重复句；现场改词按现场版本记录 |
| `status` | `sung`、`not_sung`、`uncertain` | 分清唱了、没唱、暂不确定 |
| `start` / `end` | 从文件开头计时的秒数 | 句首为实际发声开始，句尾包含唱出的延音 |
| `boundary_uncertainty_ms` | 标注容许的不确定范围 | 弱起、重混响的边界可有歧义 |
| `tags` | 拖音、和声、间奏、重复副歌等 | 按困难类型分析，而非只看总体平均 |

`not_sung` 的起止必须为 `null`；`uncertain` 可记录粗范围，但不进入主要时间误差统计。标点和全半角差异在文本匹配时归一化，真实错词不应通过归一化掩盖。

## 建议先标什么

第一阶段先标句级起止，不要求为整首歌逐字打点。每种语言选择若干有代表性的片段，包含干净独唱、密集伴奏、长音、和声、重复副歌、长间奏和现场改词。随后补充少量独立字词标注，专门评估高亮扫描。

从原始音频试听标注，尽量不要先看模型预测再修改，避免锚定偏差。歧义较大的边界标为不确定，关键样本由第二人复核。将同一首歌的不同片段和近似现场版本放在同一数据划分中，避免测试集泄漏。

真实录音、歌词、标注和统计放在 Git 忽略的 `out/evaluation/`，只在本地使用。公开仓库保留格式、虚构示例与评测程序。

## 能回答哪些问题

- **漏句率**：已确认唱出的句子中，有多少没有正确文本匹配的输出。
- **起点/终点误差**：MAE、P50、P90 和 100ms 内命中率，分别统计。
- **多余字幕**：已经确认未唱的句子是否仍被输出。
- **人工处理量代理**：多少已匹配句子的偏差超过阈值，需要进入复核。
- **适用范围**：按语言、拖音/和声等类型、模型和策略分别比较。

漏句和无效时间不能从报表中消失：误差只在有效匹配句上计算，必须同时报告匹配数、漏句率和无效行。P90 需要从实际误差样本计算，不能平均多个文件的 P90 当作总体 P90。人工复核比例是工作量代理，实际编辑次数和耗时仍需另行记录。

`timing_coverage` 用全部确定唱出的句子作分母，反映多少句能进入时间误差统计；重复句有歧义也会降低覆盖率。`missing_rate` 只对能够明确对应的唱出句计算，并非覆盖率的补数。当前命令逐录音评分；按语言、标签或模型分组汇总仍需整理多个结果，程序尚未自动生成跨录音统计。

## 运行评测

无需 GPU 或模型，使用系统 Python：

```bat
python src\evaluate_alignment.py --reference docs\examples\alignment-reference.json --prediction docs\examples\alignment-prediction.json --output out\evaluation\example-result.json
```

真实标注应另加 `--media` 指向本机实际录音，程序会核对 SHA-256。散列不一致会拒绝评测；未传媒体时结果明确标记 `media_verified: false`。

```bat
python src\evaluate_alignment.py --reference out\evaluation\reference.json --prediction out\evaluation\prediction.json --media out\evaluation\audio.wav --output out\evaluation\result.json --tolerance-ms 150
```

预测可以直接使用项目的 `align.json` / `align_vN.json` 的 `lines` 格式。若每行提供 `line_id`，按人工标注 ID 匹配；否则按歌词顺序匹配。重复文本数量不一致时，无法知道漏的是哪一次，会单独标为 `ambiguous_repeat_ids`，不强行计入时间误差；需人工建立正确的对应关系。

示例有两句确定唱出的歌词：起点误差分别为 100ms、800ms，因此 MAE 为 450ms；第二句需要时间复核。还有一行未唱和一行不确定内容，不应算成漏唱错误。

## 和网页自动验收的区别

网页验收不需要人工标注，实时检查完整性、边界、字词时间和声学风险，作用是找出需要处理的任务。评测集有独立人工答案，作用是验证版本改进是否有效。自动重试接受候选，只代表通过保守替换条件，仍需通过独立评测判断实际收益。
